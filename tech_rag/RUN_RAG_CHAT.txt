使用
1. 双击工作区根目录“启动RAG问答.cmd”，或访问 http://127.0.0.1:8876 。
2. 选择 MU/美光、TSM/台积电、NVDA/英伟达，输入研究问题。
3. “有据回答”：检索现有知识库后，由现有配置 Flash 整理回答，单题最多一次模型请求。
   询问“除了本公司新闻，还应查什么”或补充上下游搜索方向时，输出简短新闻搜索清单：
   3–6条、目标不超过300字符，每条只列环节/对象和关键词；有据项带引用，未确认方向标“待查”。
   此类问题使用固定产业链检索词，避免检索到公司官网/披露渠道等无关正文。
   具体事实或技术问答继续使用原有有据回答；同公司同时间的省略追问保留搜索清单意图。
   “只看原文”：不调用大模型，只展示检索命中、关系路径和资料缺口。
4. 点击回答中的 [1] 等编号，展开原文、页码/段落、公开时间和来源链接。
   “继续查看检索原文”只追加原文，不重新生成回答；追加片段会明确标注未参与上方回答。
5. “指定历史时点”按北京时间输入；每次提问重新检索，不把当前回答当作历史证据。
6. “导出本轮结果”保存完整 JSON，包含稳定引用 ID、来源版本及字符范围。

启动命令（已有环境，无安装）
tech_rag\integration\.venv\Scripts\python.exe tech_rag\chat_launcher.py
只检查/启动、不打开浏览器：上述命令加 --no-browser。
前台运行服务：同一 Python 执行 tech_rag\chat_server.py --port 8876。
启动器检测已有本机服务，已启动时不重复加载 BGE。仅监听 127.0.0.1。
关闭网页不会停止服务；本机进程信息保存在 tech_rag/state/rag_chat_server.json。

范围与限制
- 只使用本地科技知识库（5,026 原文块、152 条关系/证据向量及已有图文件）。
  不调用新闻、Yahoo、原生联网、TradingAgents，不写 Neo4j，不进行交易。
- 不重新下载 BGE、不向量化全部原文；现有关键词+已有 BGE 语义向量+图关系联合检索。
- 有据回答依赖已授权的根目录 apikey.env；不会在页面或日志记录认证头/密钥。
- 每题首包最多 7 处原文、10,500 字符、2 跳/12 路径，最多 3 页。
  新闻搜索清单的输出token上限为650，普通事实回答仍为1500；超长/无引用返回审查提示，不自动重试。
  本轮模型上下文有固定上限，预算不足时返回原文及提示，不静默缩掉后继续声称完整。
- 独立 chat 账本最多 30 请求/100,000 provider tokens，未知 usage 时阻断后续模型请求。
  不自动重试、不重置此前 Pro 原生搜索失败的未知账本。
- 原文命中/编号可回查不等于语义已支持结论；回答保留条件与未知，仍需人工阅读证据。
- 跨轮仅用同公司/同时间模式的近期用户问题理解“那/它”等追问；不把旧模型回答当证据。
  各轮 current 都重新冻结时间，分页使用该轮冻结时间。历史覆盖仍受原有公开时间核验边界限制。
- 对话在当前网页内保留，刷新后清空；本机 state/rag_chat 留存审查记录及实际模型上下文。
  清空网页不会删除这些本地记录。
